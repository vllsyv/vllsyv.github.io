前置知识：小白必懂的互联网原理扫盲

一、B/S 架构 vs C/S 架构

基本概念

  • C/S架构（Client/Server）
    客户端/服务器模式，用户需要安装特定客户端软件（如QQ、王者荣耀），通过客户端连接服务器进行数据交互。

  • B/S架构（Browser/Server）
    浏览器/服务器模式，用户通过浏览器直接访问网站（如淘宝、知乎），无需安装额外软件。

核心区别

特性 C/S架构 B/S架构
安装要求 需安装客户端 无需安装，只需浏览器
更新维护 客户端需手动更新 服务端更新，客户端无感
跨平台性 依赖特定系统版本 浏览器支持即可跨平台
网络依赖 部分功能可离线使用 完全依赖网络连接

应用场景

  • C/S：对性能要求高的应用（游戏、专业软件）
  • B/S：信息查询类应用（电商、新闻网站）

二、HTTP/HTTPS 协议基本原理

1. HTTP 协议特点

  • 无状态协议：每次请求独立，服务器不记录历史请求
  • 明文传输：数据未加密，安全性低
  • 默认端口：80

2. 常见请求方法

方法 作用
GET 获取资源（参数在URL中可见）
POST 提交数据（参数在请求体内）
PUT 更新整个资源
DELETE 删除资源

3. 状态码分类

状态码 含义 常见例子
1xx 信息性状态码 100（继续发送请求体）
2xx 成功 200（OK）、201（创建成功）
3xx 重定向 301（永久迁移）、302（临时重定向）
4xx 客户端错误 404（找不到资源）、403（无权限）
5xx 服务器错误 500（内部错误）、502（网关错误）

4. Cookie、Session、Token机制

  • Cookie：
    由服务器发送到浏览器的小数据片段（最大4KB），浏览器存储后每次请求自动携带，是一种浏览器机制
    cookie中通常只包含少部分信息，如sessionId,再由服务器通过sessionId查找用户session信息，从而得到用户的数据
    典型应用：记住登录状态、购物车记录

  • Session：
    服务器创建的临时用户状态存储（默认存在服务器内存中），记录用户当前会话的各种状态与信息
    安全注意：Session ID需通过Cookie或URL传递，需防范窃取

  • Token：
    Token 是一种无状态的身份验证机制，最常见的实现是 JSON Web Token（JWT），它包含所有必要的用户信息，服务器无需保存会话状态，也就免除了通过sessionId查找session再获取用户信息的过程。
    Token既可以由cookie机制进行维护，也可以自定义请求头进行维护。所以它可以支持跨域访问，实现单点登录等功能。

5. HTTPS 安全加密

  • 加密原理：SSL/TLS协议加密传输数据
  • 工作流程：
    1. 客户端请求HTTPS连接
    2. 服务器返回数字证书
    3. 客户端验证证书有效性
    4. 双方生成会话密钥用于加密通信
  • 默认端口：443

三、URL 的组成

标准结构示例

组成部分 说明
https:// 协议类型
www.example.com 域名（主机名）
:8080 端口号（默认可省略）
/path/to/page 资源路径
?key1=value1 查询参数（?开头，&分隔）
#section1 锚点（页面内定位）

四、DNS 解析过程

解析步骤

  1. 浏览器缓存查询
    检查本地是否缓存过域名对应的IP

  2. 系统缓存查询
    查看系统hosts文件和缓存记录

  3. 递归查询
    向本地DNS服务器（通常由ISP提供）发起查询请求

  4. 迭代查询

    • 本地DNS服务器向根域名服务器（.）查询
    • 根服务器返回顶级域服务器（如.com）地址
    • 本地DNS向顶级域服务器查询，获授权域名服务器地址
    • 最终从授权域名服务器获取完整IP地址

  5. 结果返回
    将IP地址返回给浏览器，并缓存结果

注意事项

  • TTL（Time To Live）：DNS记录缓存时间，控制更新频率
  • DNS预解析：HTML中可通过<link rel="dns-prefetch" href="//domain.com">提前解析

通过以上基础概念的梳理，可帮助初学者建立对互联网工作原理的系统化认知，为后续深入学习Web开发奠定基础。
