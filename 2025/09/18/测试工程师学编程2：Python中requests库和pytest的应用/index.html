作为测试工程师，我们正处在一个对技能要求日益多元化的时代。功能测试是基石，但自动化测试能力已成为提升测试效率、保证软件质量、并实现个人职业突破的关键。在众多技术栈中，Python凭借其简洁易懂的语法和极其丰富的生态系统，成为了自动化测试，特别是接口自动化测试的首选语言。

本系列文章旨在带领您，从测试的视角出发，系统地学习如何运用Python中的requests库和pytest框架，最终能工程化地构建一个接口自动化测试平台。我们将摒弃华而不实的示例，以一个真实的供应链金融项目——垫资代采功能作为业务背景，贯穿始终，让技术学习与业务实践紧密结合。

业务背景：垫资代采业务流程浅析

在我们编写第一行代码之前，深刻理解被测业务是成功设计自动化用例的前提。垫资代采是一种常见的供应链金融模式，其核心流程可以简化为：

  1. 代采单下单：客户（融资方）发起一笔代采订单，指定需要采购的货物、数量等信息。
  2. 前置风控：在正式下单前或下单时，系统必须调用风控系统，评估客户资质，获取可用额度和产品费率配置。这是流程得以继续的关键前置条件。
  3. 预付款：平台根据风控结果，代表客户向供应商支付部分货款（预付款）。
  4. 尾款 & 税款：货物到港或满足其他条件后，平台支付剩余尾款和相关税款。
  5. 入库：货物进入平台指定仓库。
  6. 客户分批赎回：客户根据自身资金情况，分批申请赎回部分货物。
  7. 抄码 & 结算单：平台进行货物抄码（确认货物信息），并生成结算单（明确本次赎回需支付的金额）。
  8. 客户付款：客户根据结算单付款。
  9. 发货：平台收到款项后，安排发货。

这个流程涉及状态多、链路长，非常适合通过接口自动化来保障各环节的稳定性和数据一致性。

第一部分：接口测试利器 - Requests库详解

接口测试的本质是模拟客户端向服务器发送请求，并验证服务器返回的响应是否符合预期。在Python世界中，requests库是完成这一任务最简单优雅的HTTP库。

1.2 发起你的第一个API请求 (GET)

风控环节通常是一个查询接口，我们假设其API为 GET /api/risk-control/{client_id}，用于获取某个客户的额度和费率。

代码解析：

  • requests.get(): 发起一个HTTP GET请求。
  • url: 请求的目标地址。
  • headers: 请求头，用于传递元信息，如认证令牌(Authorization)和内容类型(Content-Type)。
  • response: 请求返回的对象，包含所有响应信息。
  • response.status_code: HTTP状态码（如200成功，404未找到，500服务器错误）。
  • response.json(): 如果响应体是JSON格式，这个方法能直接将其解析为Python字典或列表，极其方便。
  • response.text: 以文本形式获取响应体。
  • response.headers: 响应头信息。

第二部分：测试框架核心 - Pytest详解

2.1 Pytest的核心优势与安装

核心优势：

  • 简洁明了：使用简单的assert语句进行断言，失败信息清晰易读。
  • Fixture机制：提供强大的 setUp 和 tearDown 功能，是管理测试依赖和资源（如数据库连接、初始化数据）的灵魂。
  • 参数化测试：轻松实现多组数据的驱动测试。
  • 丰富的插件生态：拥有大量插件（如pytest-html, pytest-xdist, allure-pytest）支持生成报告、并行执行等。
  • 自动发现：能自动发现和运行以test_开头或_test结尾的文件和函数。

2.3 Pytest的灵魂：Fixture

Fixture是Pytest用于实现测试前置条件（Setup）和后置清理（Teardown）的核心机制。它比传统的setUp/tearDown方法更灵活、更强大。

Fixture 作用域 (scope):

  • function (默认): 每个测试函数执行一次。
  • class: 每个测试类执行一次。
  • module: 每个模块执行一次。
  • session: 一次测试会话（执行一次pytest命令）只执行一次。获取Token这种昂贵操作非常适合用session级别。
